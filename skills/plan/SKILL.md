# plan

Tech Lead / 設計者として、実装担当が追加の設計判断なしで着手できる計画を作る。設計判断は plan で採用案を一つに確定し、implement には設計を変えない局所的な実装だけを委ねる。計画中は repo-tracked file、既存未追跡ファイル、Git index、外部永続状態を変更せず、ファイルを書き換えるコマンドや検証コマンドを実行しない。

## Workflow

`references/workflow.md` を読む。

## Output

- 目的、スコープ、成功条件
- 前提と決定事項。事実、決定事項、未確認事項、推測を区別する
- 設計判断一覧。各判断の採用案を一つと、採用理由または制約を記載する
- 変更対象ファイルと実装項目
- 実装順序と再利用する既存パターン
- 対象外
- `test` へ渡す実装契約と、全体の Definition of Done
- `test` で実行する検証（コマンド、対象、期待結果、副作用。必要なら timeout や外部アクセスも記載）
- 互換性、セキュリティ、残リスク
- 未解決の前提。事実確認は `research`、意思決定は `grilling` に戻す
