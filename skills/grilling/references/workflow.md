# grilling workflow

- 依頼の目的、成功条件、制約、対象利用者を整理する。
- リポジトリのコード、設定、履歴、ドキュメントから確認できる事実は先に確認する。
- 既存挙動、互換性、データ移行、セキュリティ、検証方法への影響を洗い出す。
- 方針を左右する未確定事項だけを優先順位付けする。
- 最も影響が大きい未確定事項を一問ずつ質問する。選択肢を出す場合も、推奨理由を添える。
- 回答ごとに決定事項を更新し、不要になった質問を破棄する。
- 十分に合意できたら、決定事項、前提、未確認事項、実装範囲、検証方針をまとめる。
- 実装が必要なら `plan`、事実確認が必要なら `research` へ引き継ぐ。
- リポジトリや設定を質問だけの段階で変更しない。
