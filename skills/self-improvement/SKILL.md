# self-improvement

会話から得た知見を、根拠のある汎用的な改善へ変換する。推測による自動学習や、承認前のファイル変更はしない。

## Workflow

1. 会話、作業結果、ユーザーの修正・判断を振り返り、候補対象の skill と関連ファイルを確認する。
2. 複数の案件で再利用でき、手順・判断基準・失敗回避策として簡潔に書ける知見だけを候補にする。秘密情報、固有事情、根拠のない好み、既存ルールと重複する文言は除外する。
3. 各候補について、対象ファイル、根拠、汎用ルール、効果、リスク、最小差分案を提示する。
4. 候補提示だけでは変更せず、候補単位の明示承認を待つ。承認後は `plan` → `implement` → `test` → `review` の順で、承認対象だけを反映する。
5. 対象ファイルや変更範囲、規則の意味を広げる必要が生じた場合は、差分案を再提示して承認を取り直す。
6. `self-improvement` 自身を対象にする場合も同じ承認ゲートを適用し、自己参照で追加候補を自動適用しない。

## Candidate format

```text
候補: <短い題名>
対象: <ファイルパス>
根拠: <会話または作業結果からの要約>
汎用ルール: <他の案件にも適用できる表現>
効果: <改善される品質・安全性・効率>
リスク: <誤適用や保守上の懸念。なければ「なし」>
差分案: <追加・変更する本文>
```

候補がない場合は、理由を一文で示して終了する。
