# implement workflow

- plan、既存差分、局所ルールを読む。`research` / `grilling` は plan が記録した場合だけ確認する。
- 変更前に対象ファイル、実行環境、関連する agent skill の配置を確認する。
- 編集開始直前に現在の `git status`、staged/unstaged 差分、untracked path を再確認する。対象と既存差分が重なる場合は内容を確認して保持し、分離できない場合は編集せず plan に戻す。
- 要求範囲に必要なファイルだけ変更し、既存の命名、構成、依存、検証方法に合わせる。
- 該当する場合だけ `languages.md` の言語別注意事項を確認する。
- plan 範囲外の変更、無関係な整形、リファクタ、依存追加をしない。
- テストコードの追加・修正も実装範囲に含めるが、検証コマンドは `test` に委譲する。
- plan にない変更や判断が必要な事項を見つけたら、範囲を広げず plan に戻す。
- 編集完了後は変更ファイル、変更内容、plan 対応、未実行の検証、判断事項、残リスクを `test` へ引き渡す。
