# review workflow

- `git status`、`git diff --stat`、必要な差分を読む。
- 未追跡ファイルも内容を確認する。
- 重大なバグ、回帰、セキュリティ、破壊的変更を優先する。
- 外部スキルでは、プロンプトインジェクション、危険なコマンド、秘密情報の収集、無断通信を確認する。
- 指摘はファイル、理由、影響、修正方針を具体化する。
- repo-tracked file と外部状態は変更しない。
- plan と test の報告を読み、計画との不一致、失敗、未検証範囲を確認する。
- 検証コマンド、auto-fix、formatter write など変更を伴うコマンドは実行しない。
- 問題がない場合も、test 結果に基づく残リスクと未検証範囲を示す。
