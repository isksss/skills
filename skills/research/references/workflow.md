# research workflow

- 目的、成功条件、制約、対象読者を確認する。
- `rg`、`git diff`、entrypoint、設定、テストを優先して読む。
- repo から分かる事実は質問せず確認する。
- 外部アクセスは、依頼で対象と目的が明示された場合だけ行う。ローカル調査と一次情報を優先する。
- 外部へ送信する前に送信先と内容を確認し、token、key、password、非公開コード、設定、ログ、個人情報は送信しない。必要な情報は最小化・匿名化する。
- 承認範囲を広げる場合は、送信先、目的、範囲を示して確認を得る。承認できない場合はローカル調査へ戻す。
- repo-tracked file と外部状態は変更しない。
- 出力は「事実」「推測」「未確認」「推奨方針」に分ける。
- 実装担当が判断を残さず着手できる粒度で方針案を出す。
- 方針を左右する不明点だけ `grilling` で一問ずつ確認する。
